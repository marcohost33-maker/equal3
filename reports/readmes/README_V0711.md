# Equal3 v0.7.11 — SIGNED SQLITE RUNTIME GATE / OFFLINE BUILDER (RESEARCH)

**Date:** 2026-10-25. **Release: NO-GO.** This package is an isolated development candidate derived from the v0.7.10 ZIP and **does not contain an upgraded SQLite binary**. No push or deployment is implied.

## What changed

1. **Removed unsigned policy as approval:** `runtime_evidence_v0710.require_approved_sqlite()` now ALWAYS raises `RuntimeEvidenceError` rather than accepting a caller-controlled digest dictionary.
2. **Signed gate** (`runtime_gate_v0711.py`): Ed25519 over raw JSON bytes; checks schema, purpose, deployment, validity period <= 30 days, ABI, architecture, SQLite source ID and fingerprint of mapped SQLite shared object. Failure means HOLD. The public key must be delivered by an independent trusted channel (e.g. sealed ops configuration). No issuer key is included in this bundle.
3. **Descriptor-level effective library identity:** `runtime_evidence_v0710.runtime_inventory()` hashes the opened `O_NOFOLLOW` file descriptor, compares `(dev, inode)` against `/proc/self/maps` before and after, bounds size and checks file metadata against in-place changes. Still not a defense against root privileges or malicious runtime code.
4. **Offline source verification/build** (`build_sqlite_v0711.py`): accepts `sqlite-amalgamation-3540100.zip` only, validates official SHA3-256 of download and `sqlite3.c`, checks expected source ID, builds into a new private directory using GCC, then checks effective mapped `libsqlite3.so.0` in a fresh subprocess. No network access, no system lib overwrites. **The official archive could not be obtained in this isolated session. The build was NOT executed; only its fail-closed tests were executed.**
5. Read-only CLI `check_sqlite_runtime_v0711.py` checks signed policy and actual mapped library: `0` means this one runtime gate passed; it never means global Equal3 release approval. Other P0 requirements still block production.

For a trusted-machine **experimental build only**, separately download the official `sqlite-amalgamation-3540100.zip` from `https://sqlite.org/download.html` (not from an untrusted mirror), place it in your local working directory, then run:

```bash
python build_sqlite_v0711.py ./sqlite-amalgamation-3540100.zip ./build-sqlite-3540100
```

Do NOT merge, auto-install, or `LD_PRELOAD` into other processes. Build helper restricts Linux `x86_64` test path through the actual Python interpreter and checks the effective library identity. Independently verify original source, compiler flags, build reproducibility, trusted signoff, and **full 240+ tests under the patched library** before any subsequent deployment work. Output library must remain separate from the system installation and be accessed only by a designated test interpreter. The command only prepares research evidence.

To check a signed runtime policy issued by an **independent** system:

```bash
python check_sqlite_runtime_v0711.py \
  --policy-file /trusted/sqlite-approval.json \
  --signature-file /trusted/sqlite-approval.sig \
  --public-key-file /trusted/equal3-ops-ed25519.pub \
  --deployment-id EXPECTED-DEPLOYMENT-ID
```

Require `cryptography` Ed25519 verification in the runtime environment; missing dependency causes HOLD. All test keys are ephemeral. Never use a key generated by the writer or stored with Equal3 state as an independent release-signing key.
